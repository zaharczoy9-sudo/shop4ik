⚡ Оптимизация Производительности

index.html (Витрина)

  • Critical CSS инлайнирован с комментарием
  • loading="lazy" на все изображения товаров
  • font-display: swap для быстрой отрисовки
  • Оптимизированный рендер списков (`.join()` вместо DOM операций)
Целевые метрики:
Lighthouse ≥ 90

admin.html (Админка)

  • Event delegation через `.closest()` (нет дублирования обработчиков)
  • Оптимизированный рендер таблицы (одноразовое создание HTML)
  • SSE live stream вместо polling
  • Мемоизация статистики

bot.js (Сервер)

  • Rate limiting: /api/order (10 req/min), /admin/api/login (8 req/min)
  • Валидация размера изображения (макс. 2 МБ)
  • MIME type validation (PNG, JPEG, WebP)
  • Cache-Control заголовки для статики

📸 Загрузка Фото вместо Эмодзи

Архитектура хранения

Характеристика Выбранный подход (Data URL) Альтернатива (Files on Server)
Формат Base64 в JSON (store.json) Файлы на диске (/data/images/)
Плюсы Нет файловой системы, одна база, простая миграция Меньше JSON, быстрее парсинг
Минусы JSON растёт (~1.3x от размера фото) Нужна настройка CORS, CDN

Структура товара

{ "id": "liq-podonki-1", "category": "liquids", "name": "Ледяной Гранат и Мята", "price": 21, "image": null, // ← новое поле (data URL или null) "icon": "🧊" // ← fallback на эмодзи }

UI в админке

  • Кнопка "📸 Выбрать фото" для выбора файла
  • Превью изображения (160×160px) при загрузке
  • Валидация: макс. 2 МБ, PNG/JPEG/WebP только
  • Кнопка "✕ Удалить" для возврата на эмодзи
  • Ошибки выводятся в реал-тайме

Отображение

  • На витрине: фото 56×56px с `loading="lazy"`
  • В админке: эскизы 40×40px в таблице товаров
  • Правило: если `image` → фото, иначе → эмодзи

🔄 Обратная Совместимость

  • Автоматическая миграция: старые товары → `image: null`
  • Плавный переход: эмодзи показываются до загрузки фото
  • Нет ломки логики: заказы, статусы, доставка работают как раньше
  • Не требуется ручная правка store.json

📝 Изменения по Файлам

index.html

+ Комментарий для критического CSS + <img loading="lazy" /> на все товары + .product-thumb img { object-fit: cover; } + Поддержка как data URL, так и эмодзи fallback

admin.html

+ .img-preview-box — контейнер превью + .img-upload-label input[type="file"] — file input (скрытый) + .img-upload-trigger — кнопка выбора + .img-remove — кнопка удаления + renderProducts() — эскизы фото в таблице + openProductModal() — расширенная форма загрузки + валидация

bot.js

+ upsertProduct() — валидация размера и MIME типа + DEFAULT_STORE.products[].image: null — новое поле + ensureStore() — миграция: image: null к старым товарам + POST /admin/api/product — принимает image (data URL)
